# 持久化、知识更新与维护

## 数据边界

Skill 源码与用户数据分开。默认建议数据目录为当前项目旁的 `personal-love-coach-data/`，只有用户已授权保存后才创建；也可明确指定其他绝对路径。按对象自定义代号建档，不从私人身份信息生成文件名。

记录最小必要信息：对象 ID、时间、用户转述/原始材料类型、事实与主观印象分别存储、关系阶段及证据、下一步与实际反馈。不同对象不可因名字相近自动合并。事实冲突记录待确认，修订须说明原因并保留历史。

回忆只选当前对象与当前任务相关的信息，标明日期和来源；旧状态不能无限沿用。把事件事实、用户偏好、关系共识和待验证解释分开，纠正一个事实时复核依赖它的结论，不把MBTI、动机猜测或模拟反应写成对象事实。现有档案Schema只存其已支持字段；更细的事件记录需要另行授权的文件，不能杜撰CLI字段。

用户要求暂停记忆时停止新增写入，仍可即时辅导；查看记录时说明实际目录和范围。用户明确要求删除时，append-only是正常审计规则，不能作为拒绝删除的理由：落实用户指定范围，涵盖相关原答、档案、归档、备份和导出，并说明实际删除情况。当前没有内置删除命令，应由具备文件权限的宿主在确认目标范围后执行，不能把暂停、归档或删除当前版本说成清除了所有副本。

工具命令见 [工具指南](../scripts/USAGE.md)。训练历史 append-only、不覆盖旧回答；单进程本地使用，工具对同时写入使用锁。个人档案更新使用 revision，先写临时文件再替换；旧版本进 archive。工具限制对象和记录 ID，拒绝路径穿越及符号链接目录。

3.3.0用单独hint-corrections记录首答提示遗漏，用practice-turns记录虚构接续；这些都属于用户数据，导出、删除和备份范围需一并考虑。新会话保存case_bindings与question_settings，成绩关联内容摘要和版本；旧会话、旧成绩不自动迁移或补造来源，版本unknown与legacy-import分别统计。元信息如审核日期的变动不等于题干变化。

3.4.0的learning-notes独立保存用户分析、教练观察和未回答状态，亦纳入授权、导出、备份和删除范围。教练观察包含适用范围、支持与反证，是待验证判断而非对象或用户人格事实。个人历史分数、原话和具体经历不能进入内置题、回放或版本评测；来源讨论只转成通用设计，示例另行独立虚构。覆盖率与缺失状态不能替代有效成绩或晋级证据。

不将私聊、完整截图、联系方式或第三方身份资料放进可分享包或模型评测。本项目内置训练题、考试题、保留评测、示例与离线回放必须独立编写为虚构内容；不得使用用户提供资料作种子、摘录或匿名化改写。用户实际辅导记录仅能在授权的独立数据目录处理，不能回填内置语料。保存位置、删除范围由用户选择；未主动设定保留期限时不悄悄删除。归档不是删除，备份需一并考虑。导出与归档不上传网络，不自动创建定时任务。

## 三层维护

- 每次事件：对象事实、互动、训练原答和反馈、待确认冲突；经授权后更新。
- 每月或版本周期：案例、风格库、规则证据、失效来源。只记录提案，不因一例有效改通用规则。
- 稳定基线：核心思维、阶段定义、五维量表、路由；需具体修订依据和回归验证才变更。

## 变更闭环

采集 → 标记事实/经验/假设 → 复核来源及许可 → 独立案例测试 → 变更日志 → 发布 → 观察并可回滚。

规则账本包含 ID、来源、原观点的简述、适配规则、适用条件、反例、证据类型、测试 ID 与复核日期。重大判断不能以源作者自评“高可信度”替代原始证据核查。

新版先运行结构、数据与脚本测试；再做行为回归，边界和事实忠实关键案例必须全部通过。固定模型和条件比较前后版本，主观自然度需独立人工盲评；有严重回退则不发布稳定版。版本包保留 SHA256 与评测条件以供恢复。

代码只承诺已经验证的机制；语义评测、多人评分一致性、真实生活迁移没有完成时必须明确标为待验证。长期复测日期不等于已发送提醒。
