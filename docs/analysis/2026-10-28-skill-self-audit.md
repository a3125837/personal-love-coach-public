# 恋爱教练3.2.0整体自检

日期：2026-10-28。检查本机源码、规则、题库、Schema、恢复与成绩流程。全部复现使用临时目录及独立虚构文本；题库变更使用内存替换，没有修改真实数据或题库。本次为审查，以下缺陷尚未修复；没有重新打包或同步GitHub。

结论：辅导框架可以使用，程序和结构检查通过，但训练记录完整性、题库覆盖与行为验证仍有缺口。不能把65项测试通过理解为不存在问题或辅导效果已经验证。

## 已确认问题

### 1. 补正提示标记会被静默忽略（优先）

位置：`personal-love-coach/scripts/coach.py`的`write_answer_unlocked`，约125–138行。

首次保存hint_used=false的原答后，以相同原文补正hint_used=true，函数仅比较answer文本，返回已保存，却没有更新或明确拒绝元数据变化。临时目录复现结果：reported_saved=true、stored_hint=false。这会使“首次作答当时实际用过提示”的补正无法可靠落盘；应与“首次独立作答后才请求提示”区分处理。

建议：完全相同重试保持幂等；元数据不同不能静默成功。明确支持带原因的提示补正并保留审计记录，或者拒绝并引导正确补正流程。既有考试会话提示检查仍然有效，本问题不等于已证明可以绕过正式考试晋级。

### 2. 会话没有绑定题干版本（优先）

位置：`show_session`、`progress_report`与会话/成绩Schema。

会话记录题号及rubric_version，没有保存题干快照、内容摘要或corpus_version。恢复时按当前题库重新取题。内存模拟同题号更新后，工具确实返回新题干与旧原答，没有报冲突。成长统计分组也没有语料版本，无法自动执行文档中“不同语料版本不得直接混算”的要求。

建议：开会话绑定题干摘要和语料版本，保留可恢复快照；恢复、评分与统计交叉检查。旧记录标记版本未知并单列，不能补造旧版本身份。

### 3. 训练成绩可以绕过会话与题目登记（优先）

位置：`append_result`约394–436行。

考试要求会话和注册考题；普通training模式没有同样的必需检查。临时目录中，未登记case_id、未开round_id的20分训练成绩被接受并判通过。这些记录可进入成长报告，削弱原答、题源与提示的可追溯性；并不直接取得考试晋级资格。

建议：常规训练按三题会话与注册题校验；历史导入或现实迁移如需保留单独入口，须明确标记来源与可信程度，不并入独立训练证据。

### 4. 任务类型没有随会话保存（次优先）

`question --task`仅控制本次题面。会话Schema没有逐题task、是否展示阶段等字段；`show-session`也不恢复这些配置。对话上下文丢失后，工具无法确认原来是判断题还是表达题。建议保存逐题教学配置，同时继续把教练内部评分资料与学员题面分开。

### 5. 分级题库不足以独立完成完整训练路径（次优先）

| 等级 | 内置训练题 | 内置考题 |
|---|---:|---:|
| Lv0 | 3 | 0 |
| Lv1 | 3 | 0 |
| Lv2 | 12 | 6 |
| Lv3 | 5 | 3 |
| Lv4 | 6 | 0 |
| Lv5 | 7 | 1 |
| Lv6 | 2 | 0 |

两轮晋级至少需6道不同的同等级考题，目前只有Lv2满足这一数量条件。Lv6甚至不足以直接选齐同级三道训练题。流程允许教练原创注册新题，但临时出题的一致难度和评分质量没有得到验证。建议优先补齐各级最小路径，再补阶段、题型和反馈分支覆盖，避免只追求总题数。

### 6. 训练工具的读题范围与文字隔离要求不完全一致（次优先）

`question`调用`load_catalog`，该函数读取训练、考试与保留集后才检查所选题的split。输出白名单确实不展示内部评分资料，也拒绝直接展示考试/保留题；但内部仍读取了非训练资料，不符合训练不读取这些集合的严格描述。建议按用途加载集合，同时保留注册时的跨集合重复检查。这不是已复现的学员题面泄漏。

## 内容与验证不足

- 关系递进：已有P1–P8、三条判断线和推进/维持/后撤框架，但尚缺不同阶段下“相似信号、不同含义”的成组对照练习；部分边界仍依赖教练解释。
- 互动提高：已补情绪识别、表达、接续与退出规则，但58道原题没有因此全面升级成多轮脚本。接续默认仅在当前对话中，没有结构化持久化与恢复。任务切换也不会自动重写原题干，仍需教练检查适配性。
- 评分校准：五维各0–4有通用锚点，尚无足够独立评分者对同一组答案的一致性结果。反馈判断、互动处理与关系推进可能对同一问题重复扣分，需要校准示例说明何时分别计分。
- 行为验证：65项程序回归与结构校验本次再次通过；新增针对记录完整性的复现暴露了现有测试盲点。8条新行为探针尚未执行真实模型与人工评审，而且主要是单次请求，不能证明长期、多轮或实际生活迁移效果。
- 功能完整性：暂停记忆、查看和删除已有执行规则，未实现统一管理CLI；第七项旧核心思维仍明确缺原文。两者均不应描述为已完整自动化。

## 修正顺序

先修提示补正、题干版本绑定和训练记录入口；随后补逐题任务恢复与按用途读题；再补齐分级题库、进行多轮行为评审和评分校准。保留六模式、八段式和五维20分，不需要为解决这些问题引入额外人格代理或新的总分体系。
